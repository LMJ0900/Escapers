# 로그인 에러 명세서

## 1. 에러 분류

로그인 플로우에서 발생하는 에러는 발생 위치에 따라 4가지로 나눈다.

| 구분                  | 발생 위치            | 사용자 노출 방식              | 예                                    |
| --------------------- | ------------------- | ---------------------------- | ------------------------------------- |
| A. 클라이언트 검증    | 브라우저(제출 전)   | 입력 필드 하단 인라인 메시지  | 이메일 형식 오류, 비밀번호 규칙 위반  |
| B. 인증/비즈니스 에러 | 서버 API 응답       | 폼 상단 알림(배너) 또는 토스트 | 자격증명 불일치, 계정 잠금, 탈퇴 계정 |
| C. 소셜 로그인 에러   | OAuth 리다이렉트 후 | 로그인 페이지 알림           | 사용자 취소, 이메일 미제공, 연동 실패 |
| D. 네트워크/시스템    | 전송 계층 / 서버 5xx | 토스트 + 재시도 버튼         | 타임아웃, 오프라인, 서버 오류        |

## 2. 공통 에러 응답 포맷 (B, C, D 서버 응답)

```jsonc
// HTTP 4xx / 5xx
{
  "code": "AUTH_INVALID_CREDENTIALS", // 프론트 분기용 안정적 식별자 (문자열 상수)
  "message": "이메일 또는 비밀번호가 올바르지 않습니다.", // 사용자 노출 가능한 기본 문구
  "status": 401,                       // HTTP 상태 (본문에도 중복 포함)
}
```

원칙

- **프론트는 `message` 문자열이 아니라 `code` 로 분기한다.** `message` 문구는 언제든 바뀔 수 있다.
- `code` 를 모르는 경우(정의되지 않은 값) → "일시적인 오류가 발생했습니다. 잠시 후 다시 시도해주세요." 로 폴백.
- 계정 존재 여부가 드러나는 문구를 쓰지 않는다(`FR-AUTH-04` 인수 조건). 아이디 없음/비밀번호 틀림을 모두 `AUTH_INVALID_CREDENTIALS` 하나로 응답.


```ts
// src/api/auth/response/LoginRes.ts (추가 예정)
export interface LoginErrorResponse {
  code: LoginErrorCode;
  message: string;
  status: number;
}

export type LoginErrorCode =
  | "AUTH_INVALID_CREDENTIALS"
  | "AUTH_VALIDATION_FAILED"
  | "AUTH_ACCOUNT_LOCKED"
  | "AUTH_ACCOUNT_SUSPENDED"
  | "AUTH_ACCOUNT_WITHDRAWN"
  | "AUTH_EMAIL_NOT_VERIFIED"
  | "AUTH_SOCIAL_ONLY"
  | "AUTH_RATE_LIMITED"
  | "AUTH_OAUTH_CANCELED"
  | "AUTH_OAUTH_EMAIL_MISSING"
  | "AUTH_OAUTH_FAILED"
  | "AUTH_SESSION_EXPIRED"
  | "INTERNAL_ERROR";
```

## 3. A. 클라이언트 검증 에러 (제출 전)

[`loginRequestSchema`](../src/api/auth/request/LoginReq.ts) (zod) + `react-hook-form` (`mode: "onChange"`) 로 검증한다. 메시지는 스키마에 정의된 문구를 그대로 노출하며, 해당 필드 하단에 인라인 표시한다. 검증 실패 시 제출 버튼이 비활성화된다.

| 코드 (제안)            | 필드     | 조건                                                     | 메시지                                         | 상태 |
| ---------------------- | -------- | ------------------------------------------------------- | --------------------------------------------- | ---- |
| `VAL_EMAIL_REQUIRED`   | email    | 빈 값                                                   | 이메일을 입력해주세요.                        | 구현 |
| `VAL_EMAIL_FORMAT`     | email    | 이메일 형식 아님 (`z.email`)                            | 이메일 형식이 올바르지 않습니다.              | 구현 |
| `VAL_PASSWORD_LENGTH`  | password | 8자 미만 또는 16자 초과                                 | 비밀번호는 8자 이상 16자 이하여야 합니다.     | 구현 |
| `VAL_PASSWORD_COMPLEX` | password | 영문/숫자/특수문자 조합 아님 (`/^(?=.*[A-Za-z])(?=.*[0-9])(?=.*[^A-Za-z0-9]).+$/`) | 비밀번호는 영문 숫자 특수문자의 조합이어야 합니다. | 구현 |

> 클라이언트 검증 "코드"는 zod 스키마에 명시돼 있지 않다(메시지만 존재). 위 코드 값은 QA/버그 리포트에서 케이스를 지칭하기 위한 편의 명칭이다. 필요 시 `loginRequestSchema` 각 `refine`/`pipe` 에 `{ error: ... }` 대신 커스텀 이슈 `code` 를 부여하는 방안을 검토한다.

### 주의

- 서버도 동일 규칙을 재검증해야 한다. 클라이언트를 우회한 요청에는 `AUTH_VALIDATION_FAILED` (400) 로 응답한다.
- 비밀번호 규칙은 로그인 시 굳이 강하게 막지 않는 선택지도 있다(기존 회원의 과거 비밀번호가 현재 정책과 다를 수 있음). 정책 확정 필요 — **미결 사항 1** 참고.

## 4. B. 인증 / 비즈니스 에러 (`POST /api/auth/login`)

성공 시 `200` + `{ accessJwt, refreshJwt }` ([`LoginResponse`](../src/api/auth/response/LoginRes.ts)). 실패 응답은 아래와 같다.

| HTTP | code                       | 발생 조건                                              | 사용자 메시지                                                       | 프론트 처리                                                     | 상태 |
| ---- | -------------------------- | ---------------------------------------------------- | ---------------------------------------------------------------- | ------------------------------------------------------------- | ---- |
| 400  | `AUTH_VALIDATION_FAILED`   | 서버 재검증 실패(형식/필수값), JSON 파싱 실패          | 입력값을 다시 확인해주세요.                                        | 폼 상단 배너. 가능하면 `detail.fields` 로 필드 매핑            | 예정 |
| 401  | `AUTH_INVALID_CREDENTIALS` | 이메일 미존재 **또는** 비밀번호 불일치                  | 이메일 또는 비밀번호가 올바르지 않습니다.                          | 폼 상단 배너. 비밀번호 필드 초기화, 이메일 유지                | 구현(목) |
| 401  | `AUTH_EMAIL_NOT_VERIFIED`  | 자격증명은 맞으나 이메일 인증 미완료(`FR-AUTH-01`)      | 이메일 인증이 완료되지 않았습니다. 받은 편지함을 확인해주세요.      | 배너 + "인증 메일 재발송" 버튼 노출                            | 예정 |
| 403  | `AUTH_ACCOUNT_SUSPENDED`   | `User.status = suspended` (`FR-ADM-03`)               | 이용이 제한된 계정입니다. 자세한 내용은 고객센터로 문의해주세요.   | 배너. 제재 사유/기간이 있으면 `detail` 로 표시                 | 예정 |
| 403  | `AUTH_ACCOUNT_WITHDRAWN`   | `User.status = withdrawn` (`FR-AUTH-09`)              | 탈퇴한 계정입니다.                                                | 배너 + 회원가입 링크 안내                                     | 예정 |
| 409  | `AUTH_SOCIAL_ONLY`         | 소셜 가입 계정으로 비밀번호 로그인 시도(로컬 비밀번호 없음) | 소셜 로그인으로 가입한 계정입니다. OO 로그인으로 시도해주세요.     | 배너 + 해당 소셜 버튼 강조. `detail.provider` 활용            | 예정 |
| 423  | `AUTH_ACCOUNT_LOCKED`      | 로그인 5회 연속 실패로 일시 잠금(`FR-AUTH-08`, 예: 5분) | 로그인 시도가 많아 계정이 잠겼습니다. 약 N분 후 다시 시도해주세요. | 배너 + `detail.retryAfter` 로 카운트다운. 제출 버튼 비활성화  | 예정 |
| 429  | `AUTH_RATE_LIMITED`        | IP/디바이스 단위 요청 과다(무차별 방어, 비기능 8.2)     | 요청이 너무 많습니다. 잠시 후 다시 시도해주세요.                   | 토스트 + `Retry-After` 헤더/`detail.retryAfter` 존중          | 예정 |

### 케이스 노트

- **`401 AUTH_INVALID_CREDENTIALS`** — 아이디 없음과 비밀번호 틀림을 구분하지 않는다(계정 열거 방지). 목([`handler.ts`](../src/mocks/handler.ts))이 `mock@test.com` / `test1234!` 이외 모든 조합에 대해 반환하는 현재 유일한 에러다.
- **`423` vs `429`** — `423`(Locked)은 "특정 계정"이 실패 누적으로 잠긴 상태, `429`(Too Many Requests)는 "요청 출처(IP 등)"의 레이트리밋. 백엔드 구현에 따라 `423` 대신 `429` + `code: AUTH_ACCOUNT_LOCKED` 조합을 쓸 수도 있으니 **프론트는 `code` 기준으로 처리**한다.
- 캡차 대체(`FR-AUTH-08`)를 도입하면 `AUTH_ACCOUNT_LOCKED` 응답의 `detail.captchaRequired: true` 로 신호하고, 프론트는 캡차 위젯을 렌더한다.

## 5. C. 소셜 로그인 에러 (Google / Kakao / Naver OAuth) (예정)

`FR-AUTH-05`. 현재 [`SocialLoginForm`](../src/app/login/_component/SocialLoginForm/SocialLoginForm.tsx)은 `console.warn("... 아직 연동되지 않았습니다.")` 만 수행한다(전부 `예정`).

플로우: 버튼 클릭 → `GET /api/auth/oauth/:provider` 로 이동 → 제공자 동의 화면 → `GET /api/auth/oauth/:provider/callback?code=&state=` → 서버가 세션/JWT 발급 후 앱으로 리다이렉트. 에러는 콜백 처리 후 로그인 페이지로 `?error=<code>` 쿼리와 함께 리다이렉트해 표시한다.

| 단계         | code                       | 발생 조건                                                       | 사용자 메시지                                                       |
| ------------ | -------------------------- | ------------------------------------------------------------- | ---------------------------------------------------------------- |
| 클라이언트   | `AUTH_OAUTH_NOT_CONFIGURED`| 제공자 키/리다이렉트 URI 미설정 (개발 중)                       | 소셜 로그인이 아직 준비 중입니다.                                  |
| 제공자 동의  | `AUTH_OAUTH_CANCELED`      | 사용자가 동의 화면에서 취소 (`error=access_denied`)             | 소셜 로그인을 취소했습니다.                                        |
| 콜백         | `AUTH_OAUTH_STATE_MISMATCH`| `state` 불일치/만료 (CSRF 방어, 세션 유실, 뒤로가기 재요청)     | 인증 세션이 만료되었습니다. 다시 시도해주세요.                     |
| 콜백         | `AUTH_OAUTH_EMAIL_MISSING` | 제공자가 이메일 미제공(카카오 이메일 미동의 등)                 | 이메일 제공에 동의해야 가입할 수 있습니다.                         |
| 콜백         | `AUTH_OAUTH_EMAIL_TAKEN`   | 같은 이메일의 로컬(또는 다른 소셜) 계정이 이미 존재             | 이미 OO 이메일로 가입된 계정이 있습니다. 기존 방식으로 로그인해주세요. |
| 콜백         | `AUTH_OAUTH_FAILED`        | 토큰 교환 실패, 제공자 5xx, 알 수 없는 오류                     | 소셜 로그인에 실패했습니다. 잠시 후 다시 시도해주세요.             |
| 최초 로그인  | `AUTH_NICKNAME_REQUIRED`   | 최초 소셜 로그인 → 닉네임 설정 단계 필요 (에러 아님, 분기 신호) | (닉네임 설정 화면으로 이동)                                        |

> `AUTH_NICKNAME_REQUIRED` 는 실패가 아니라 "추가 온보딩 필요" 신호다. 200 응답 본문에 `{ needsProfile: true }` 형태로 내려주는 편이 낫다.

## 6. D. 네트워크 / 시스템 에러 (예정)

전송 계층 또는 서버 5xx. TanStack Query `useMutation` 의 `onError` 에서 공통 처리한다.

| 상황                       | 판별                                        | code             | 사용자 메시지                                          | 프론트 처리                     |
| -------------------------- | ------------------------------------------ | ---------------- | --------------------------------------------------- | ------------------------------- |
| 오프라인                   | `navigator.onLine === false` / fetch reject | `NETWORK_OFFLINE`| 인터넷 연결을 확인해주세요.                            | 토스트, 재시도 버튼             |
| 타임아웃                   | AbortController 타임아웃(예: 10s)            | `NETWORK_TIMEOUT`| 응답이 지연되고 있습니다. 잠시 후 다시 시도해주세요.   | 토스트, 재시도 버튼             |
| 서버 오류                  | HTTP 500 / 502 / 503 / 504                   | `INTERNAL_ERROR` | 일시적인 오류가 발생했습니다. 잠시 후 다시 시도해주세요. | 토스트. Sentry 등에 리포트(8.6) |
| 잘못된 응답 형식           | JSON 파싱 실패, 스키마 불일치                 | `INVALID_RESPONSE`| 일시적인 오류가 발생했습니다.                          | 토스트. 에러 로깅               |
| CORS / 네트워크 정책 차단  | fetch `TypeError`                            | `NETWORK_BLOCKED`| 네트워크 연결에 문제가 있습니다.                       | 토스트                          |
| 인증 만료(로그인 유지 실패) | 저장된 `refreshJwt` 로 재발급 실패           | `AUTH_SESSION_EXPIRED` | 다시 로그인해주세요.                              | 로그인 페이지로 이동            |

## 7. 프론트엔드 처리 가이드

### 7.1 노출 위치 규칙

| 에러 구분        | 노출 컴포넌트                          |
| ---------------- | ------------------------------------- |
| A. 필드 검증     | `InputBox` 의 `error` prop (인라인)   |
| B. 인증/비즈니스 | 폼 상단 배너(`role="alert"`)          |
| C. 소셜          | 로그인 페이지 상단 배너               |
| D. 네트워크/시스템 | 전역 토스트 + 재시도                 |

### 7.2 코드 → 메시지 매핑 (예시)

```ts
// src/api/auth/loginErrorMessage.ts (예정)
const LOGIN_ERROR_MESSAGE: Record<string, string> = {
  AUTH_INVALID_CREDENTIALS: "이메일 또는 비밀번호가 올바르지 않습니다.",
  AUTH_EMAIL_NOT_VERIFIED: "이메일 인증이 완료되지 않았습니다. 받은 편지함을 확인해주세요.",
  AUTH_ACCOUNT_SUSPENDED: "이용이 제한된 계정입니다. 고객센터로 문의해주세요.",
  AUTH_ACCOUNT_WITHDRAWN: "탈퇴한 계정입니다.",
  AUTH_ACCOUNT_LOCKED: "로그인 시도가 많아 계정이 잠겼습니다. 잠시 후 다시 시도해주세요.",
  AUTH_RATE_LIMITED: "요청이 너무 많습니다. 잠시 후 다시 시도해주세요.",
  AUTH_SOCIAL_ONLY: "소셜 로그인으로 가입한 계정입니다.",
  AUTH_OAUTH_CANCELED: "소셜 로그인을 취소했습니다.",
  AUTH_OAUTH_EMAIL_MISSING: "이메일 제공에 동의해야 로그인할 수 있습니다.",
  AUTH_OAUTH_FAILED: "소셜 로그인에 실패했습니다. 잠시 후 다시 시도해주세요.",
  AUTH_SESSION_EXPIRED: "다시 로그인해주세요.",
  INTERNAL_ERROR: "일시적인 오류가 발생했습니다. 잠시 후 다시 시도해주세요.",
};

export const getLoginErrorMessage = (code?: string) =>
  (code && LOGIN_ERROR_MESSAGE[code]) ??
  "일시적인 오류가 발생했습니다. 잠시 후 다시 시도해주세요.";
```

## 8. QA 체크리스트

- [ ] 이메일 빈 값 / 형식 오류 → 인라인 메시지, 제출 버튼 비활성
- [ ] 비밀번호 7자 / 17자 / 규칙 미충족 → 인라인 메시지
- [ ] 목 계정(`mock@test.com` / `test1234!`) → 로그인 성공, 토큰 수신
- [ ] 틀린 비밀번호 → 401 배너, 비밀번호 필드만 초기화, 이메일 유지

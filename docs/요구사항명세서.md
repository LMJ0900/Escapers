## 1. 개요

### 1.1 목적

방탈출 카페의 **테마 정보 · 지점 위치 · 이용자 리뷰**를 한곳에서 제공하고, 회원 간 소통(게시판 · 댓글 · 좋아요)이 가능한 커뮤니티형 리뷰 서비스를 구축한다. 본 문서는 초기 버전(MVP + 커뮤니티 확장) 범위의 기능/비기능 요구사항을 정의한다.

### 1.2 범위

- **포함**: 회원/인증, 프로필, 테마·지점 정보, 지도/위치 API, 리뷰·평점, 게시판, 댓글(대댓글·스포일러 가림), 좋아요, 검색/필터, 신고/기본 관리.
- **불포함(차기 과제)**: 예약/결제 연동, 매장 사장님 전용 어드민, 모바일 네이티브 앱, 추천 알고리즘 고도화, 다국어.

### 1.3 용어 정의

| 용어          | 정의                                                              |
| ------------- | ----------------------------------------------------------------- |
| 카페(Cafe)    | 방탈출 브랜드의 한 매장(지점). 예: "키이스케이프 강남"            |
| 지점(Branch)  | 카페의 물리적 위치 단위. 주소·좌표·영업정보를 가진다              |
| 테마(Theme)   | 한 지점에서 운영하는 개별 방(시나리오). 리뷰의 기본 대상          |
| 리뷰(Review)  | 특정 테마에 대한 회원의 평가(별점 + 플레이 기록 + 후기 본문)      |
| 스포일러 댓글 | 문제/장치/결말 정보를 포함해 기본적으로 가려서 표시하는 댓글·리뷰 |
| 좋아요(Like)  | 리뷰·게시글·댓글에 대한 회원의 공감 표시 (회원당 1회 토글)        |

### 1.4 참고

- 기술 스택: Next.js 16 (App Router) · React 19 · TypeScript · CSS (전역 CSS + CSS Modules) · TanStack Query.

### 1.5 개발 환경 · 코드 규약

- **스타일**: 전역 색상 팔레트(`src/styles/colors.css`) + 시맨틱 토큰·클래스(`src/styles/semantic.css`) + CSS Modules 를 함께 쓴다. 클래스 바인딩은 `bindClassNames`(`src/util/BindClassName.ts`)로 하며, 등록되지 않은 키는 전역 시맨틱 클래스로 그대로 통과시킨다.
- **컴포넌트 스캐폴딩**: `npm run createComponent`(`scripts/createComponent.mjs`, 외부 의존성 없음). 공용은 `src/components/`, 라우트 전용은 `src/app/<route>/_component/` 에 생성한다.
- **린트 · 포맷**: ESLint(코드 품질) + Prettier(포맷)를 분리하고 `eslint-config-prettier` 로 규칙 충돌을 제거한다. `.vscode/` 공유 설정으로 저장 시 자동 적용된다. 커밋 전 `lint` · `typecheck` · `format:check` 통과가 병합 조건이다.
- 세부 사항은 `README.md` 참조.

## 2. 서비스 개요

### 2.1 목표 사용자

| 유형          | 설명                  | 주요 목적                                          |
| ------------- | --------------------- | -------------------------------------------------- |
| 비회원 방문자 | 로그인 없이 탐색      | 테마 검색, 리뷰·평점 열람, 지점 위치 확인          |
| 일반 회원     | 가입 후 활동          | 리뷰 작성, 게시판/댓글, 좋아요, 프로필 관리        |
| 파워 유저     | 다수 플레이 기록 보유 | 워터마크 표시                                      |
| 관리자(Admin) | 운영 담당             | 신고 처리, 콘텐츠/회원 관리, 테마·지점 데이터 관리 |

### 2.2 핵심 사용자 시나리오

1. 방문자가 "홍대 공포"로 검색 → 평점순 테마 목록 → 상세에서 리뷰와 지도상의 지점 위치 확인.
2. 회원이 플레이 후 리뷰 작성(별점·성공여부·남은시간·힌트수·후기). 장치 설명은 "스포일러" 체크 후 작성.
3. 다른 회원이 리뷰의 스포일러 영역을 클릭해서 펼쳐 보고, 도움이 되면 좋아요.
4. 회원이 자유게시판에 "4인팟 구합니다" 글 작성 → 댓글로 모집 진행.
5. 부적절한 댓글을 회원이 신고 → 관리자가 검토 후 숨김 처리.

### 2.3 시스템 구성(개략)

```
[Next.js App Router]
 ├─ 서버 컴포넌트 / Route Handler (BFF)
 ├─ 인증: JWT 기반 (accessToken + refreshToken, 이메일 + 소셜 OAuth)
 ├─ DB: 관계형(PostgreSQL) — 회원/테마/지점/리뷰/게시판/댓글/좋아요/신고
 ├─ 파일: 이미지 스토리지(오브젝트 스토리지 + CDN)
 └─ 외부 연동: 지도 API(카카오맵/네이버), 소셜 로그인(Kakao/Google/Naver)
```

## 3. 기능 요구사항

표기: **우선순위** = P0(필수·MVP) / P1(중요) / P2(선택). 각 요구사항은 `FR-<모듈>-<번호>` 식별자를 가진다.

### 3.1 회원 · 인증 (AUTH)

| ID         | 요구사항                                                                                   | 우선순위 |
| ---------- | ------------------------------------------------------------------------------------------ | -------- |
| FR-AUTH-01 | 이메일 + 비밀번호로 회원가입한다. 필수: 이메일, 비밀번호, 닉네임. 이메일 인증 메일 발송.   | P0       |
| FR-AUTH-02 | 이메일 또는 닉네임 중복 시 가입을 거부하고 사유를 안내한다.                                | P0       |
| FR-AUTH-03 | 비밀번호 정책: 최소 8자, 영문+숫자 포함. 서버는 해시(bcrypt/argon2)로만 저장한다.          | P0       |
| FR-AUTH-04 | 이메일/비밀번호로 로그인하고 JWT(accessToken + refreshToken)를 발급한다.                   | P0       |
| FR-AUTH-05 | 소셜 로그인(Kakao, Google, Naver 중 최소 1종)을 지원한다. 최초 로그인 시 닉네임 설정 단계. | P1       |
| FR-AUTH-06 | 로그아웃 시 세션/토큰을 무효화한다.                                                        | P0       |
| FR-AUTH-07 | 비밀번호 재설정: 등록 이메일로 만료 시간이 있는 재설정 링크를 발송한다.                    | P1       |
| FR-AUTH-08 | 로그인 실패 5회 연속 시 일시적 잠금(예: 5분) 또는 캡차 노출.                               | P1       |
| FR-AUTH-09 | 회원 탈퇴: 개인정보는 파기하고, 작성 콘텐츠는 "탈퇴한 사용자"로 익명화 후 보존한다.        | P1       |
| FR-AUTH-10 | 인증이 필요한 동작(작성/좋아요/신고)에 비회원이 접근하면 로그인 화면으로 유도한다.         | P0       |

**인수 조건 예시 (FR-AUTH-04)**

- 올바른 자격증명 → 200, accessToken/refreshToken 쿠키(HttpOnly, Secure, SameSite=Lax) 설정, 내 프로필 조회 가능.
- 틀린 비밀번호 → 401, "이메일 또는 비밀번호가 올바르지 않습니다" (계정 존재 여부 노출 금지).

### 3.5 리뷰 · 평점 (REVIEW)

| FR-REV-03 | 본인 리뷰 수정·삭제 가능. 삭제 시 소프트 삭제 후 평점 재집계.                                                                                         | P0       |
| FR-REV-04 | 리뷰 등록/수정/삭제 시 해당 테마의 `ratingAvg`, `reviewCount`를 재계산한다(소수 첫째 자리 반올림).                                                    | P0       |
| FR-REV-05 | 리뷰 목록 정렬: 최신순 / 좋아요순 / 평점 높은순 / 낮은순. 페이지네이션(무한 스크롤 허용).                                                             | P0       |
| FR-REV-06 | **스포일러 처리**: 리뷰 작성 시 "스포일러 포함" 토글. 켜진 리뷰의 본문은 목록/상세에서 블러 + "스포일러 보기" 버튼으로 가리고, 클릭 시에만 펼친다.    | P0       |
| FR-REV-07 | 리뷰 본문 일부 구간만 스포일러 마킹(`                                                                                                                 |          | 가린 텍스트 |     | ` 문법 또는 에디터 버튼)도 지원한다. | P1  |
| FR-REV-08 | 별점 없이 후기만, 후기 없이 별점만 등 최소 입력 규칙을 정의한다(별점 필수, 본문 최소 10자 권장).                                                      | P1       |
| FR-REV-09 | 이미지 첨부(최대 N장), 용량/포맷 제한, EXIF 위치정보 제거.                                                                                            | P1       |
| FR-REV-10 | 리뷰 신고(스포일러 미표기 / 광고 / 비방). 신고 누적 임계치 초과 시 자동 블라인드 + 관리자 큐 등록.                                                    | P1       |
| FR-REV-11 | 자기 리뷰에는 좋아요 불가.                                                                                                                            | P1       |

**인수 조건 예시 (FR-REV-06)**

- 스포일러 리뷰는 초기 렌더링 시 본문 텍스트가 DOM에 노출되더라도 시각적으로 완전히 가려진다(블러 + 오버레이).
- "스포일러 보기" 클릭 → 해당 리뷰만 펼쳐짐. 다시 접기 가능. 펼침 상태는 페이지 이동 전까지 유지.
- 비회원도 펼쳐볼 수 있다(로그인 불필요).

## 5. API 개요 (초안)

REST 기준 예시. 세부 스펙(요청/응답 스키마, 에러 코드)은 API 명세서에서 확정.

### 인증

- `POST /api/auth/signup` · `POST /api/auth/login` · `POST /api/auth/logout`
- `POST /api/auth/password/forgot` · `POST /api/auth/password/reset`
- `GET /api/auth/oauth/:provider` · `GET /api/auth/oauth/:provider/callback`
- `GET /api/me`

### 테마 · 지점 · 지도

- `GET /api/themes?q=&location=&genre=&sort=&page=`
- `GET /api/themes/:id`
- `GET /api/branches?bbox=` 또는 `?lat=&lng=&radius=`
- `GET /api/branches/:id`
- (admin) `POST/PATCH/DELETE /api/themes/:id`, `/api/branches/:id`

### 리뷰

- `GET /api/themes/:id/reviews?sort=&page=`
- `POST /api/themes/:id/reviews` · `PATCH /api/reviews/:id` · `DELETE /api/reviews/:id`
- `POST /api/reviews/:id/like` (토글)

### 게시판 · 댓글

- `GET /api/posts?category=&q=&sort=&page=` · `GET /api/posts/:id`
- `POST /api/posts` · `PATCH /api/posts/:id` · `DELETE /api/posts/:id`
- `GET /api/comments?targetType=&targetId=` · `POST /api/comments` · `PATCH /api/comments/:id` · `DELETE /api/comments/:id`
- `POST /api/posts/:id/like` · `POST /api/comments/:id/like` (토글)

### 프로필 · 좋아요 · 알림 · 신고

- `GET /api/users/:nickname` · `PATCH /api/me/profile`
- `GET /api/me/likes?type=` · `GET /api/me/bookmarks`
- `GET /api/notifications` · `POST /api/notifications/read`
- `POST /api/reports`
- (admin) `GET /api/admin/reports` · `POST /api/admin/reports/:id/resolve`

**공통 규칙**: 인증 필요 엔드포인트는 401/403 구분, 목록은 커서 또는 offset 페이지네이션, 쓰기 요청은 CSRF 방어 및 rate limit 적용, 응답 시간·좋아요 등 카운터는 집계 컬럼 우선.

## 8. 비기능 요구사항

### 8.1 성능

- 주요 목록 페이지 서버 응답 P95 < 500ms(캐시 적중 시 < 150ms), LCP < 2.5s(모바일 4G 기준).
- 지도 마커 조회는 현재 뷰포트 기준 최대 200개로 제한, 초과 시 클러스터링.
- 좋아요·조회수 등 고빈도 쓰기는 집계 컬럼 + 비동기 반영으로 처리.

### 8.2 보안

- 비밀번호 해시(argon2id/bcrypt), 세션 쿠키 HttpOnly·Secure·SameSite, 전 구간 HTTPS.
- 입력 검증/이스케이프로 XSS·SQL 인젝션 방지. 리치 텍스트는 화이트리스트 기반 새니타이즈.
- 지도/소셜 API 키는 서버 환경변수, 클라이언트 노출 키는 도메인·레퍼러 제한.
- 신고·인증·작성 엔드포인트 rate limiting, 무차별 로그인 방어.
- 업로드 이미지: 확장자·MIME·용량 검증, 이미지 재인코딩, EXIF(GPS 포함) 제거.

### 8.3 개인정보 · 정책

- 개인정보 처리방침·이용약관 페이지 필수. 회원가입 시 필수 동의(약관, 개인정보), 선택 동의(마케팅) 분리.
- 만 14세 미만 가입 제한 고지.
- 탈퇴 시 개인 식별정보 파기, 게시물은 익명화 보존 또는 사용자 선택 삭제.
- 위치정보는 조회 시점에만 사용하고 서버에 개인 위치 이력을 저장하지 않는다.

### 8.4 사용성 · 접근성

- 모바일 우선 반응형. 주요 플로우는 터치 타깃 44px 이상.
- WCAG 2.1 AA 지향: 명도 대비, 키보드 내비게이션, 스포일러 토글에 `aria-expanded`/스크린리더 라벨.
- 스포일러 콘텐츠는 텍스트 선택·복사로도 우회 노출되지 않도록 펼치기 전 실제 텍스트를 렌더링하지 않는다(서버가 마스킹 또는 지연 로드).

### 8.5 호환성

- 최신 2개 메이저 버전의 Chrome, Safari, Edge, Firefox 및 iOS/Android 모바일 브라우저.
- 다크 모드 지원.

### 8.6 운영 · 관측

- 구조화 로깅, 에러 트래킹(예: Sentry), 기본 지표 대시보드(요청량·에러율·지연).
- DB 일 1회 백업, 마이그레이션은 버전 관리.
- 시드/목 데이터로 로컬·스테이징 구동 가능(현재 `src/lib/mock/store.ts` 대체 예정).

### 8.7 국제화 (차기)

- 텍스트는 리소스 분리 구조로 작성하되 1차 릴리스는 한국어만.

## 9. 제약 조건 및 가정

- 지도/소셜 로그인은 외부 서비스 약관·쿼터에 종속된다(무료 쿼터 초과 시 유료 전환 필요).
- 테마·지점 데이터는 초기에 관리자가 수기 입력하며, 공식 오픈 API가 없는 브랜드가 많다.
- MVP는 단일 리전 배포, 트래픽 급증 대비 수평 확장은 차기.
- 결제·예약은 범위 밖이며 외부 예약 페이지로 링크아웃한다.

## 10. 릴리스 범위 제안

| 단계              | 포함 기능                                                                                                           |
| ----------------- | ------------------------------------------------------------------------------------------------------------------- |
| **M1 (MVP)**      | 이메일 인증, 테마 목록/상세, 지점 정보+미니 지도, 리뷰 CRUD+평점 집계, 스포일러 리뷰 가림, 리뷰 좋아요, 기본 프로필 |
| **M2 (커뮤니티)** | 게시판(자유·모집·질문), 댓글·대댓글+스포일러 댓글, 게시글/댓글 좋아요, 알림함, 신고+관리자 기본                     |
| **M3 (확장)**     | 소셜 로그인, 지도 탐색/내 주변, 통합 검색·고급 필터, 찜, 활동 통계, 감사 로그, 자동 블라인드 규칙                   |

## 11. 미결 사항 (확정 필요)

1. ~~인증 방식: 세션(쿠키) vs JWT~~ → **JWT로 결정.** accessToken/refreshToken 쿠키 발급 + 만료 시 자동 재발급(proxy).
2. 지도 제공사: 카카오맵 vs 네이버 지도 (쿼터·이용약관·좌표계 비교).
3. 리치 텍스트 에디터: 마크다운 vs WYSIWYG.
4. 이미지 스토리지: 자체(S3 호환) vs 외부 이미지 CDN.
5. 리뷰 정책: 테마당 1리뷰 고정 vs 재플레이 다중 리뷰 허용.
6. 스포일러 마스킹 수위: 전체 가림만 vs 구간 마킹까지 1차 포함.
7. 검색 인프라: DB LIKE/전문검색 vs 별도 검색엔진(예: Meilisearch) 도입 시점.
